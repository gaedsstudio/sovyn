# Code of Conduct

## Our Commitment

SOVYN is an open-source project built around transparent, reliable, and respectful collaboration.

We are committed to maintaining a welcoming environment for everyone who participates in the project, regardless of experience level, background, identity, location, or role.

## Expected Behavior

Participants are expected to:

- Treat others with respect.
- Give constructive and specific feedback.
- Discuss ideas and code without attacking individuals.
- Respect different levels of experience and technical knowledge.
- Accept reasonable criticism and corrections.
- Keep technical discussions focused on improving SOVYN.
- Respect project security, privacy, and responsible disclosure practices.
- Avoid intentionally misleading contributors or users.
- Help maintain a productive environment for developers, testers, and users.

## Unacceptable Behavior

The following behavior is not acceptable:

- Harassment, threats, intimidation, or personal attacks.
- Discriminatory or hateful language.
- Deliberate disruption of discussions, issues, pull requests, or development work.
- Publishing another person's private information without permission.
- Sharing private credentials, tokens, API keys, or other sensitive information.
- Intentionally introducing malicious code, backdoors, spyware, credential theft, or hidden telemetry.
- Attempting to bypass SOVYN's security or permission systems without responsible disclosure.
- Spam, repeated self-promotion, or unrelated advertising.
- Impersonating project maintainers, contributors, or other users.

## Technical Disagreements

Disagreement is normal in an open-source project.

When discussing architecture, implementation, security, performance, or product direction:

- Explain the technical reasoning behind your position.
- Provide evidence, tests, benchmarks, or reproducible examples where possible.
- Critique the implementation rather than the person who wrote it.
- Be willing to revise your position when better evidence is presented.

The goal is to improve the project, not to win an argument.

## Security Issues

Potential security vulnerabilities should be handled responsibly.

Do not publicly disclose sensitive exploits, credentials, or vulnerabilities before maintainers have had a reasonable opportunity to investigate them.

Never include real secrets, access tokens, private keys, or personal credentials in issues, pull requests, logs, screenshots, or test fixtures.

## Enforcement

Project maintainers may edit, remove, reject, lock, or moderate contributions and discussions that violate this Code of Conduct.

Depending on the severity or frequency of the behavior, actions may include:

- A private or public warning.
- Removal of comments or contributions.
- Temporary restriction from project spaces.
- Permanent restriction from participating in the project.

Serious security abuse, harassment, threats, or malicious contributions may result in immediate removal without prior warning.

## Scope

This Code of Conduct applies to official SOVYN project spaces, including:

- GitHub repositories
- Issues and pull requests
- Discussions
- Documentation
- Community channels
- Other spaces officially operated for SOVYN development or support

It may also apply when someone is publicly representing the SOVYN project.

## Reporting

If you experience or observe behavior that violates this Code of Conduct, report it privately to the project maintainers when possible.

Reports should include enough context for the situation to be reviewed fairly.

Good-faith reports will be handled with discretion.

## Project Principle

SOVYN should remain a place where people can build, question, test, disagree, and improve the software without hostility or unnecessary barriers.

Respect the people.

Challenge the ideas.

Protect the users.
